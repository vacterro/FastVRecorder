# 0. MISSION

Создать полноценное, компактное, быстрое, полностью портативное приложение для записи голоса с микрофона.

Основной пользовательский сценарий:

1. Пользователь запускает FastVRecorder.
2. Один раз указывает папку для записей.
3. При необходимости выбирает микрофон и настраивает горячие клавиши.
4. Сворачивает приложение в системный трей.
5. Нажимает `Alt + 0` из любого обычного Windows-приложения.
6. Начинается запись микрофона, воспроизводится `start.wav`.
7. Повторно нажимает `Alt + 0`.
8. Запись корректно завершается, файл сохраняется, воспроизводится `done.wav`.
9. Пользователь продолжает заниматься своими делами.

Приложение не должно требовать ежедневного взаимодействия с интерфейсом, ручного обслуживания, настройки сложных аудиопараметров, установки дополнительных программ или повторного выбора папок.

**Основная философия: Open → Configure → Forget → Record.**

Это не DAW, не OBS, не аудиоредактор и не студия звукозаписи.

Это персональный, чрезвычайно надёжный voice recorder, доступный по одной комбинации клавиш.

# 4. MAIN RECORDING ENGINE

## 4.1. Supported recording states

Реализовать явную state machine:

```text
IDLE
  → STARTING
  → RECORDING
  → STOPPING
  → FINALIZING
  → IDLE
```

Дополнительные состояния:

```text
RECOVERING
ERROR
PAUSED — если реализована пауза
```

Требования:

- Единый authoritative recording state.
- UI, tray, hotkeys и file writer используют один источник состояния.
- Нельзя открыть две параллельные записи.
- Нельзя начать новую запись поверх незавершённой финализации.
- Повторные команды не должны приводить к double-dispose.
- Переходы атомарны и сериализованы.
- Повторное событие остановки безопасно.
- Автоматическое восстановление IDLE после устранимой ошибки.
- Исключить race conditions при быстрых повторных нажатиях.

Основной Toggle Recording не должен зависеть от того, какое окно находится в фокусе.

## 4.2. Audio capture

Использовать WASAPI shared mode.

По умолчанию:

- Default Windows recording device.
- WAV.
- PCM 16-bit.
- Mono.
- 48 kHz.
- Без нормализации.
- Без AGC, шумоподавления и автоматического удаления тишины.
- Без записи desktop audio.

Если выбранная частота или формат напрямую не поддерживаются устройством, захватывать звук в поддерживаемом формате и выполнять корректное преобразование.

Не интерпретировать floating-point samples как PCM integer.

Корректно учитывать channel count, sample rate, block alignment и формат устройства.

Записывать поток непосредственно на диск через ограниченный буфер.

Не накапливать всю запись в оперативной памяти.

Не блокировать audio callback файловыми операциями, UI-обновлениями или тяжёлым кодированием.

Очередь должна иметь определённые границы. Переполнение не должно приводить к скрытой потере аудио: при неустранимой проблеме сохранить доступные данные и явно сообщить об ошибке.

Приложение обязано выдерживать многочасовые записи.

Для WAV учитывать ограничение размера RIFF. При необходимости реализовать безопасную автоматическую сегментацию до достижения предела или подтверждённую поддержку RF64.

Никакого silent corruption.

## 4.3. Recording lifecycle

START:

1. Проверить настройки.
2. Проверить целевую папку.
3. Проверить доступное место.
4. Разрешить выбранное устройство.
5. Зарезервировать уникальное имя.
6. Открыть временный файл.
7. Запустить захват.
8. Подтвердить успешный переход в RECORDING.
9. Воспроизвести start cue.
10. Обновить UI и tray.

STOP:

1. Перейти в STOPPING.
2. Остановить поступление новых аудиоданных.
3. Дождаться завершения callback.
4. Записать оставшиеся данные.
5. Завершить WAV header или encoder.
6. Выполнить flush.
7. Закрыть file handles.
8. Проверить минимальную структурную целостность результата.
9. Переименовать временный файл в итоговый без перезаписи существующего.
10. Добавить запись в History.
11. Воспроизвести done cue.
12. Перейти в IDLE.

`done.wav` воспроизводится исключительно после подтверждённого успешного сохранения.

Если запись не сохранилась, нельзя сообщать об успехе.

# 7. CRASH RECOVERY — P0

Потеря записи вследствие падения приложения недопустима, если аудиоданные физически сохранились и могут быть восстановлены.

Во время записи использовать промежуточный файл:

```text
2026-11-26_05-36-00.wav.part
```

И recovery metadata, достаточные для восстановления:

```text
2026-11-26_05-36-00.wav.recovery.json
```

Хранить:

- Format.
- Sample rate.
- Channel count.
- Bits per sample.
- Block alignment.
- Start timestamp.
- Intended output path.
- Recording identifier.
- Recovery schema version.

Предпочесть self-describing recoverable audio format. Metadata не должны быть единственной точкой отказа.

Периодически выполнять flush с разумным интервалом, по умолчанию ориентировочно 1–2 секунды, после измерения влияния на latency и disk usage.

На следующем запуске:

1. Найти принадлежащие приложению незавершённые записи.
2. Проверить структуру и metadata.
3. Определить количество корректных аудиоданных.
4. Отбросить только неполный последний sample frame при необходимости.
5. Восстановить заголовок.
6. Создать отдельный recoverable WAV.
7. Проверить воспроизводимость.
8. Показать результат в History.

Пример:

```text
2026-11-26_05-36-00_RECOVERED.wav
```

Исходные повреждённые данные не удалять до успешной верификации recovery.

Не выдавать восстановление за полноценную запись, если часть данных потеряна.

Обработать следующие сценарии:

- Process kill.
- System crash.
- Forced reboot.
- Out of memory.
- Disk full.
- USB microphone disconnect.
- Recording folder disconnect.
- Failure during WAV finalization.
- Failure during encoding.
- Failure during atomic rename.

Файлы, которые восстановить не удалось, сохранять для последующей диагностики.

Не удалять пользовательские записи автоматически.

Не обещать восстановление данных, которые ОС или накопитель не успели физически сохранить.

# 15. PORTABLE SETTINGS

Canonical storage:

```text
FastVRecorder/
├── FastVRecorder.exe
├── config/
│   ├── settings.json
│   ├── settings.json.bak
│   └── history.json
├── media/
├── themes/
└── Recordings/
```

Допускается упаковка immutable assets непосредственно в EXE с возможностью portable override через соседние папки.

Настройки хранятся относительно application root, а не текущего рабочего каталога процесса.

Требования:

- Atomic settings writes.
- Schema version.
- Backward-compatible migration.
- Backup previous valid settings.
- Validation.
- Safe defaults.
- Recovery after malformed JSON.
- Preservation of valid settings при отсутствии отдельных полей.

Не сохранять абсолютные пути для ресурсов самого приложения.

Если пользователь выбирает папку внутри portable root, сохранять переносимый относительный путь.

Для внешней пользовательской папки допускается абсолютный путь.

После перемещения portable folder:

- Themes работают.
- Sound assets работают.
- Default recording folder корректно пересчитывается.
- Settings не сбрасываются.
- Hotkeys сохраняются.

Отдельно обработать read-only portable directory.

Не переключаться скрытно на AppData. Показать понятное состояние невозможности сохранения настроек.
